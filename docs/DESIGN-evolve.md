# DESIGN-evolve — 单流融合：把"演化方向"和"演化多少"拆到一条线里

> 2026-09-06。来源：GPT 严肃分析 + Owner 拍板的方向，落在现有 RingKoSpace A 的 `--evolve` 开关。
> 状态：**A/B 完成 → 同预算未通过，待 128M/长预算复核**（2026-09-06 本机 RTX 4060，900 万 token，dim512/L8/seq256/bs16）。

## 1. 动机

现有 A 主线的候选 `z = SiLU(Wz·conv(x))` 是**纯当前输入内容**，不含旧状态：
`h = a·h + (1−a)·z` 只能"保留或覆盖"，旧状态没有一条"被演化后继续用"的通道。

GPT 的批评：真正的单流应该把两件事分开——

| 角色 | 负责 | 式子 |
|---|---|---|
| SSM | "如果更新，往哪个方向走" | 候选含演化项 `A·h + B·x` |
| CfC(门) | "这一步走多远" | `g_t ∈ (0,1)` 步长 |
| 输入 | "现在发生了什么" | `x_t` |

统一更新：`h_t = h_{t-1} + g_t ⊙ (SSM(h_{t-1},x_t) − h_{t-1})` —— 单状态、非双流。

## 2. 在 A 上的最小实现（保持 scan 闭式）

不引入第二状态，把旧状态演化并入候选、再被 (1−keep) 门控：

```
a_evo = σ(Wa·conv(x)) ∈ (0,1)                # 每通道：旧状态演化比例
h_t   = [keep + (1−keep)·a_evo] · h_{t-1}
        + (1−keep)·(1−a_evo) · z_t
```
- 有效保留 `keep_eff = keep + (1−keep)·a_evo ∈ (0,1)` → **log-space chunk scan 依旧闭式、可并行**。
- `g = 1−keep` 是"更新强度"，`a_evo` 是"旧状态被演化后参与候选多少"——两个控制分开。
- 读侧/conv/D·x/无残差全部不动。开关：`--evolve 1`。

## 3. 消融阶梯（同一个开关家族，逐个加回去）

| 档 | g / a_evo | 语义 | 状态 |
|---|---|---|---|
| 0 | `keep=exp(−Δ·exp(A_log))`，无 a_evo | 输入相关 g(x)，纯内容写（现 A） | 已验 1.795/1.278 |
| 1 | 上述 + `a_evo=σ(Wa·x)` | 候选携带旧状态演化（g(x) + evolution） | **本 A/B** |
| 2 | `a_evo=c`（可学习常数） | 固定演化比例 | 待测 |
| 3 | `g(x,h,Δt)` backbone 门（顺序） | 真 CfC 风格，破坏并行 | 待测（若 1 有效） |

## 4. 无残差纪律与受控恒等路径 —— 必须正视

`h + g⊙(cand − h)` 数学上含受控恒等项 `(1−g)·h`。field 判死残差是因**固定加性捷径 + tied head** 退化成 unigram 打分机；`(1−g)h` 是 per-dim 受控、且门从输入来，不构成那条固定捷径。但**它仍可能被 byte-CE 当拐杖学**——这正是本 A/B 要测的：若同预算破不了 1.278（或只在 carry 涨、窗口 loss 不涨），说明演化项没带来表达增益，按纪律否掉。

## 5. 判定门槛

- 同预算同域 eval 必须压 baseline；只看 carry/长程涨不算数（要单独合成任务证）。
- 门/演化权重观察：`a_evo` 若坍缩到 0.5 附近无分化 = 退化无信息，否。
- 通过后再考虑 3 档真 CfC(Δt) 对照与 streaming-state 主线的合并顺序。

### 5b. A/B 结果（2026-09-06 本机 4060，900 万 token，dim512/L8/seq256/bs16）

| 档 | 参数 | final eval | eval 轨迹（300/600/900/1200/1500 步） |
|---|---|---|---|
| 0 baseline (A) | 6.47M | **2.0043** | 3.16 → 2.48 → 2.23 → 2.11 → 2.04 |
| 1 fused-evolve | 8.57M (+32%) | **2.0151** | **3.07** → 2.45 → 2.23 → 2.12 → 2.05 |

- **同 token 预算下 evolve 未破 baseline**（+0.011，参数多 32%）；carry 两档均正（900 万 token 太短，跨窗未启用；evolve stream2 +0.0065 vs baseline +0.0167，略不伤但无正增益）。
- 信号：evolve **早期收敛明显更快**（300 步 3.07 vs 3.16），后期被参数欠训（同 token 喂更多参数）稀释。
- **判定**：短预算否，不进 v0 主线。保留开关，**待 128M 长预算按参数对齐复核**（同 params 而非仅同 token）。

ringkospace-train --steps 1800 --dim 512 --layers 8 --seq 256 --batch 16 \
    --max-tokens 9000000 --data-root ./data/skypile --evolve 0
